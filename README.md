# QuantumTeam

Расчёт кривой бескупонной доходности MOEX и её стресс-сценариев.
Функции находятся в `src/domain/curve`, новые библиотеки для математики не нужны.

## Что рассчитано

- `nelson_siegel_rate(t, b1, b2, b3, t1)` — классическая модель Нельсона–Сигеля;
  результат в единицах входных коэффициентов.
- `moex_rate(t, params)` — модель MOEX с девятью гауссовыми поправками.
  Сырые B1–B3 и G1–G9 из ISS задаются в базисных пунктах.
- `build_base_curve(params, target_tenors=None)` — точки на сетке в месяцах.
- `interpolate_curve(points, target_tenors=None)` — линейная интерполяция;
  вне диапазона продолжается крайний отрезок, единственный узел даёт плоскую кривую.
- `irrbb_shift_bp(t, scenario, currency="RUB", shock_sizes=None)` — сдвиг в б.п.
- `apply_shift(base, shift_map, rate_floor=None)` — пользовательские узловые сдвиги.
  Между узлами сдвиг линейный, вне диапазона — крайнее значение.
- `apply_irrbb_scenario(base, scenario, currency="RUB", ...)` — точное вычисление
  стандартного шока на каждом сроке базовой кривой.

Срок `t` в формулах задаётся в годах; `tenor_months` в точках — в месяцах.
Ставки в точках и БД — **непрерывно начисляемые, в долях**:
`0.10` означает непрерывную ставку 10%. Эффективная годовая доходность:
`math.expm1(rate)`; значение MOEX `yearyields.value` равно ей, умноженной на 100.
Дисконт-фактор при такой ставке: `math.exp(-rate * t)`.

Формула MOEX:

```text
x = t / tau
F = (1 - exp(-x)) / x; при x=0: F=1
G(t) = B1 + B2*F + B3*(F-exp(-x))
       + sum(Gi * exp(-((t-ai)/bi)^2), i=1..9)
rate(t) = G(t) / 10000
a1=0, b1=0.6; a(i+1)=ai+bi; b(i+1)=1.6*bi
```

При нулевом сроке NS-часть равна `B1+B2`.
Отсутствующие или NULL G считаются нулевыми.
NaN, бесконечности, отрицательные сроки, неположительная tau и повторные узлы
интерполяции отклоняются с `ValueError`.

`point_type` описывает положение относительно опубликованной сетки MOEX.
Все ставки построены по параметрической модели; `observed` означает совпадение
срока с сеткой, а не непосредственную рыночную котировку.

## Сценарии по приложенной методике

Использованы глава 3 и таблица 3 рекомендаций Банка России 8-МР (2020),
а также Annex 2 IRRBB (2016). Это фиксированная методика из предоставленных
документов, а не автоматическая проверка актуальных нормативных требований.

Для RUB: P=400, S=500, L=300 базисных пунктов; `q=exp(-t/4)`.

| Код | Сдвиг в базисных пунктах |
| --- | --- |
| parallel_up | +P |
| parallel_down | -P |
| short_up | +S*q |
| short_down | -S*q |
| steepener | -0.65*S*q + 0.9*L*(1-q) |
| flattener | +0.8*S*q - 0.6*L*(1-q) |

Поддержаны валюты таблицы 3 из 8-МР и явный код OTHER.
При неизвестном коде — ошибка; можно передать собственные
`shock_sizes=(parallel_bp, short_bp, long_bp)`.
Для INR выбран длинный шок 350 б.п. из 8-МР; таблица Basel 2016 содержит 300.
Ограничение ставок снизу по умолчанию отсутствует; `rate_floor=0` задаёт нулевое.
В результате `shift_bp` отражает фактический сдвиг после ограничения.

Стандартные сценарии вычисляются на сетке кривой. Для регуляторных временных
интервалов можно передать середины интервалов в годах в `irrbb_shift_bp`.
Расчёт NII по методике требует двух параллельных сценариев; остальные четыре
используются для EVE. NPV/NII портфеля и факторный анализ не реализованы:
здесь сделана запрошенная расчётная часть для кривых.

## Пример

```python
from domain.curve.builder import build_base_curve
from domain.curve.shifts import apply_irrbb_scenario

base = build_base_curve({"b1": 1000, "b2": 0, "b3": 0, "t1": 1})
stressed = apply_irrbb_scenario(base, "steepener")
```

## Быстрый запуск без Docker

Из терминала WSL в корне репозитория:

```bash
PYTHONPATH=src python3 -m scripts.calculate_curves
```

Для загрузки настоящих параметров MOEX нужен `httpx`:
`PYTHONPATH=src python3 -m scripts.calculate_curves --live`.

Для API и всех тестов установите зависимости из `pyproject.toml`
в своё Python-окружение (Python 3.11 или новее).

PowerShell с созданным при проверке Windows-окружением:

```powershell
$env:PYTHONPATH = (Resolve-Path src).ProviderPath
.venv/Scripts/python.exe -m scripts.calculate_curves
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Windows-окружение `.venv` нельзя использовать как Linux-окружение WSL.

## Запуск сервисов

```bash
docker compose up -d --build
docker compose run --rm api python -m scripts.demo_pipeline
```

API: `http://localhost:8000/docs`; Airflow: `http://localhost:8080`;
RQ dashboard: `http://localhost:9181`.

Airflow выполняет вычисления в отдельном Python-окружении внутри своего
контейнера: это исключает конфликт SQLAlchemy 1.x у Airflow 2.9 и SQLAlchemy 2.x
у проекта. DAG запускает тот же скрипт `scripts.demo_pipeline`, что и ручной расчёт.
Airflow использует часовой пояс по умолчанию UTC.

Пайплайн создаёт шесть сценариев `irrbb_rub_*`, не меняя пользовательские.
Повторный запуск за ту же дату обновляет тот же снимок, а повторный пересчёт
заменяет точки. Статус `built` ставится после сохранения сценариев.
При переходе со старого прототипа старые рассчитанные ставки нужно пересчитать:
ранее сырые базисные пункты сохранялись как доли и игнорировались G-поправки.
Старые демонстрационные сценарии в существующей БД автоматически не удаляются
и не переименовываются; для методики выбирайте новые `irrbb_rub_*`.

## Проверки

`tests/test_curves.py` проверяет ручные примеры IRRBB на сроке 3.5 года,
все девять поправок, единицы, интерполяцию, сдвиги, пределы и некорректные данные.
В `tests/fixtures/moex_zcyc.json` сохранён публичный ответ MOEX от 2026-10-30:
сравнение эффективных доходностей допускает половину единицы последнего
опубликованного десятичного знака (0.00005 процентного пункта).

Интеграционные тесты требуют отдельной PostgreSQL БД и переменных
`RUN_INTEGRATION_TESTS=1`, `DATABASE_URL=postgresql+psycopg://...`.
Они проверяют повторный пересчёт, хранение и чтение результатов через API.
Без флага эти тесты пропускаются.

Источники:
[MOEX — модель и единицы](https://www.moex.com/a3642),
[MOEX — методика](https://www.moex.com/a3644),
[MOEX ISS](https://iss.moex.com/iss/engines/stock/zcyc.json),
приложенные 8-МР (2020) и IRRBB (2016).


## Демонстрационная страница

После запуска API откройте http://localhost:8000/ .
Страница показывает базовую кривую и выбранный сценарий на графике и в таблице.
Можно выбрать один из последних 100 готовых снимков, обновить отображение
или нажать «Рассчитать MOEX», чтобы загрузить ставки и выполнить расчёт.

HTML, CSS и JavaScript находятся в `src/api/static`; страница раздаётся FastAPI.
Отдельной сборки, Node.js, CDN и дополнительных библиотек не требуется.
График построен средствами SVG; проценты отображаются как `rate * 100`,
без изменения исходных непрерывных ставок.

Новые API: `GET /api/v1/curves` (готовые снимки) и
`POST /api/v1/curves/rebuild` (загрузка MOEX и расчёт).
